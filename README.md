# Jack in the Board 電子領収書（QR・署名付き）

サーバーもメールも使わない電子領収書です。スタッフの端末で発行し、購入者は自分のスマホでPDFを保存します。

## しくみ

1. スタッフが `issuer.html` で宛名・数量を入力して発行する
2. 内容をこの端末だけが持つ秘密鍵で電子署名し、データと署名を詰めたURLをQRで表示する
3. 購入者がQRを読むと `receipt.html` が開く。公開鍵で署名を検証し、正規のものなら領収書を表示してPDFを保存できる

URLを1文字でも書き換えると署名が合わず「正規の領収書として検証できません」と表示され、PDFは作れません。
PDF右下のQRから、経理担当者なども後から真正性を確認できます。

## 公開手順（GitHub Pages）

1. 新しいリポジトリ（例：`jitb-receipt`、Public）に `issuer.html` と `receipt.html` を置く
2. Settings → Pages → Branch: `main` / `(root)` → Save
3. `https://<ユーザー名>.github.io/jitb-receipt/issuer.html` をスタッフの端末で開く
4. 「設定」→「鍵を作成」→「公開鍵をコピー」
5. `receipt.html` の `PUBLIC_KEYS` に公開鍵を貼り付けてpushする
6. 「設定」の「購入者ページのURL」に `https://<ユーザー名>.github.io/jitb-receipt/receipt.html` を入力して保存
7. テストで1件発行して、別のスマホで読み取り、PDFが保存できるか確認する
8. 「次の番号」を 1 に戻して保存

## 鍵の扱い

- 秘密鍵は発行端末のブラウザの中にだけあり、GitHubには上がりません。issuer.html が公開されていても、鍵がなければ正規の領収書は作れません。
- **必ずバックアップを取ってください**（設定 →「バックアップを表示」）。パスワード管理アプリなどに保存します。iPhoneのSafariは、しばらく開かないサイトのデータを消すことがあります。
- 端末を2台使うときは、2台目で「バックアップから復元」し、領収書番号の接頭辞を変えます（例：`GM26A-` と `GM26B-`）。
- 鍵を作り直した場合は、新しい公開鍵を `PUBLIC_KEYS` に**追加**します。古い鍵を消すと、過去の領収書が検証できなくなります。

## 店番の人の端末で発行する

1. 自分の端末の issuer.html →「設定」→「店番用リンクを作成」
2. 名前・接頭辞（人ごとに別。例：`GM26B-`）・発行できる期間を入れて「リンクを作成」
3. できたリンクを店番の人に個別に送る（LINEの個別トークなど）
4. 店番の人がそのリンクを開けば、その端末で発行できるようになる

- 店番の人に渡るのは店番専用の鍵だけ。あなたの鍵は渡らない。
- 店番の鍵で作れるのは、割り当てた接頭辞の番号で、期間内の日付の領収書だけ。期間外の日付や、あなたの番号帯（`GM26A-`）を名乗る領収書は検証で弾かれる。
- リンクを知っている人は、期間内なら誰でも発行できる。グループや公開の場には貼らないこと。
- 期間はイベント当日だけにしておくのがおすすめ。
- 万一リンクが漏れたら、作成済み一覧に出る鍵を `receipt.html` の `REVOKED_STAFF_KEYS` に入れれば無効にできる。ただし、その店番が発行した正規の領収書も検証できなくなる。
- 店番の端末の発行履歴は、その端末にしか残らない。イベント後に履歴タブからCSVを書き出して送ってもらうこと。

## 当日の注意

- 会場に入る前に issuer.html を一度開いておく（QRライブラリを読み込むため）。
- 履歴タブからCSVを書き出せます。freeeへの売上入力に使えます。
- 電子発行の領収書には、金額にかかわらず収入印紙は不要です。

## 設定場所

- 発行者表記（屋号・X・住所・登録番号）：`receipt.html` の `ISSUER`
- 品目・価格・但し書き・番号接頭辞：`issuer.html` の `CONFIG`
